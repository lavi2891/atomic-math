## מקרא סטטוסים

| סטטוס | משמעות |
|---|---|
| `REQUIRED` | חלק פעיל ונדרש ב־runtime או בנתיב backend פעיל. |
| `REQUIRED_FOR_COMPATIBILITY` | דרוש זמנית בגלל נתונים, API או תוכן ישן. |
| `DEVELOPMENT_ONLY` | כלי פיתוח, בדיקה ידנית או authoring שאינו חלק מחוויית התלמיד הרגילה. |
| `TEST_ONLY` | נטען רק בסקריפטי בדיקה. |
| `GENERATED_BUT_REQUIRED` | תוצר generated שנדרש ל־build או להפעלה. |
| `POTENTIALLY_REMOVABLE` | אין לו נתיב runtime חי, אך יש blocker מתועד לפני הסרה. |
| `OBSOLETE/UNUSED` | לא נמצאו imports, scripts או שימוש runtime; אפשר להסיר בשלב cleanup מאושר. |

## כניסות וזרימות ארכיטקטוניות

### אתחול frontend

`index.html` יוצר `#root` → `src/main.tsx` טוען CSS ומרנדר `App` בתוך `ErrorBoundary` → `src/App.tsx` יוצר את pool התוכן דרך `selectQuestionPool`, טוען `StudentHomeService`, מפעיל `SyncCoordinator` ומציג `StudentHomeScreen`. הפרמטר `?playground=1` עוקף את Home ומציג `PlaygroundScreen`.

### זרימת תרגול

`StudentHomeScreen` → `resolveQuickPracticeScope`, `assignmentSessionLaunch` או `SessionSetupScreen` → `StudentPracticeService.start` → `createPracticeSession` → `SessionView` → `useSessionEngine` → `filterChallengeContent` + `SkillQuestionSelector` → `resolveQuestionDefinition` → `pickNextQuestion` → `QuestionView` → `useQuestionSolve` + `evaluateAnswer` → `createAttemptFromAnswer` → `DurableAttemptRepository` → `IndexedDbPersistenceDriver` → `projectMastery` → `SyncCoordinator` → `StudentPracticeService.finish` → `SessionSummaryScreen`.

### זרימת backend

`AppsScriptClient.request` → Web App `doPost` ב־`apps-script/Code.gs` → dispatch לפי `action` → validators ו־`amProjectMastery_` ב־`Core.gs` → קריאה/כתיבה ל־Sheets דרך helpers ב־`Code.gs` → עדכון Sheet בשם `Mastery` → response ל־client. `Setup.gs` מגדיר schema ופעולות תחזוקה ידניות.

### זרימת תוכן

`domains.ts` + `skills.ts` + `skillGroups.ts` + `policies.ts` + `challengeProfiles.ts` → `assertValidCatalog` → `FOUNDATIONAL_QUESTIONS` → `CONTENT_READINESS`/`readyDefinitions` → `questionPools.ts` → `filterChallengeContent` → `SkillQuestionSelector` → `buildGeneratedQuestion` או Question קבועה → `QuestionView`.

1. `README.md` ו־`ARCHITECTURE.md` אומרים שה־signed-number adapter עדיין מזין תוכן פעיל; מאז Phase 7B זה כבר אינו נכון. כיום `FOUNDATIONAL_QUESTIONS` מוזן ישירות.
2. `selectQuestionPool(topicId)` מתעלם בפועל מ־`topicId`; זה סימן API compatibility ברור.
3. frontend Evidence Coverage עשיר יותר מה־backend schema. `difficultyBand` ו־`category` אינם נכתבים ל־Sheet, ולכן teacher diagnostics עתידי לא יוכל לשחזר אותם מהשרת בלי migration.
4. `PersonalBests` הם local-only. מחיקת site data מוחקת אותם, ואין cross-device PB.
5. `MemoryPersistenceDriver` אינו test-only: הוא fallback runtime כש־`indexedDB` אינו זמין.
6. תיקיית `docs` מוחרגת כברירת מחדל; מסמך חדש דורש `git add -f` או שינוי מדיניות. הדבר עלול לגרום למסמכים חשובים להישאר מקומיים בלי כוונה.
7. `project-overview.md` וה־public JSON מתארים pipeline קודם ואינם מתארים את 27 ה־Skills הפעילים.

## סדר קריאה מומלץ למפתח/ת

1. `README.md` — תמונת מוצר קצרה, עם הסתייגויות העדכניות במסמך זה.
2. `docs/ARCHITECTURE.md` ואז `docs/PHASE_7A_CONTENT_PLAN.md` — גבולות והמודל הפדגוגי.
3. `src/main.tsx` ו־`src/App.tsx` — lifecycle והחלפת מסכים.
4. `src/app/studentHome/StudentHomeService.ts` ו־`StudentHomeScreen.tsx` — startup, offline וכניסת התלמיד.
5. `src/content/catalog/*`, `src/content/readiness.ts`, `src/content/foundations/questions.ts` — זהויות ותוכן פעיל.
6. `src/app/session/StudentPracticeService.ts`, `SessionView.tsx`, `useSessionEngine.ts` — תזמור התרגול.
7. `src/domain/session/*` — reducer, balancing, challenge profiles ובחירת שאלה.
8. `src/domain/questions/types.ts`, `generator/*`, `evaluators.ts` — מודל והפקת Questions.
9. `src/domain/attempts/*` ו־`src/domain/mastery/*` — מקור הראיות וה־projection.
10. `src/infrastructure/persistence/*` — IndexedDB ו־repository adapters.
11. `src/infrastructure/sync/*` — queue, client ו־failure policy.
12. `apps-script/Code.gs`, `Core.gs`, `Setup.gs` יחד עם `SETUP.md` — backend ו־Sheets schema.
13. `scripts/test-*.ts` ו־`validate-content.ts` — החוזים שמגינים על ההתנהגות.
14. רק לבסוף: ענפי `legacy`, `expr-gen/topics/signedNumbers`, הבנק הישן והמסמכים ההיסטוריים.

## סיכום תחזוקתי

ליבת המוצר הפעילה מסודרת היטב סביב `Attempt → Mastery`, catalog אטומי, readiness ו־offline-first persistence. החוב העיקרי אינו כפילות repositories אלא גבול migration לא גמור: שמות `TopicId` ו־signed-number נשארו ב־API ובבדיקות אף שהתוכן הפעיל עבר ל־foundations; במקביל, backend evidence schema טרם הדביק את metadata החדש. סדר cleanup בטוח הוא: לתקן תיעוד stale, להעביר את type של `SkillQuestionDefinition`, להפריד core מתמטי פעיל מ־legacy generation, ורק אז להסיר artifacts וקבצים שאומתו כלא בשימוש.
